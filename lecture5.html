Core Definitions
Project

A set of interrelated activities that must be performed using limited resources — men, machines, materials, money, and time.

Project Network

A diagram describing all project activities and their precedence relationships. Shows which activities must be completed before others can begin.

Event (Node)

The completion or beginning of an activity. Represented as a circle in the network diagram.

Arrow (Arc)

Represents an activity in the AOA model. The tail is the start event and the head is the end event of that activity.

Dummy Activity

A fictitious zero-duration activity (dashed arrow) used to clarify precedence when two activities share the same start and end nodes.

Critical Path

The longest path through the network — it defines the minimum time to complete the project. Any delay on this path delays the whole project.

AON — Activity-On-Node

Nodes represent activities. Arrows show precedence (dependency) between activities.

AOA — Activity-On-Arc

Arrows represent activities. Nodes are events (points in time). May need dummy activities.

CPM — Critical Path Method

Used when activity durations are known with certainty (deterministic). Focuses on scheduling and identifying which activities cannot be delayed without extending the project.

Best for: construction, manufacturing, well-defined processes

PERT — Program Evaluation & Review Technique

Used when activity durations are uncertain (probabilistic). Uses three time estimates per activity and a beta distribution to model uncertainty.

Best for: R&D, software projects, novel activities
CPM — Notations & Method
Ei = Earliest event time Lj = Latest event time Dij = Duration ES = Early Start EF = Early Finish LS = Late Start LF = Late Finish

Forward Pass → Earliest Times

Start at node 1 (E₁ = 0), move left to right. At each node, take the maximum of all incoming paths.

Earliest time of node j: Eⱼ = max{ Eᵢ + Dᵢⱼ } (for all i→j)
Early Start & Finish: ESᵢⱼ = Eᵢ EFᵢⱼ = Eᵢ + Dᵢⱼ

Backward Pass ← Latest Times

Start at last node (Lₙ = Eₙ), move right to left. At each node, take the minimum of all outgoing paths.

Latest time of node i: Lᵢ = min{ Lⱼ − Dᵢⱼ } (for all i→j)
Late Start & Finish: LFᵢⱼ = Lⱼ LSᵢⱼ = Lⱼ − Dᵢⱼ

3 Conditions for a Critical Path Activity

An activity (i,j) lies on the critical path if and only if all three conditions hold:

ESᵢ = LSᵢ
Earliest start = Latest start at node i
EFⱼ = LFⱼ
Earliest finish = Latest finish at node j
EFⱼ − ESᵢ = Dᵢⱼ
Duration = Finish − Start (zero slack)
Slack (Float) = LSᵢⱼ − ESᵢⱼ = LFᵢⱼ − EFᵢⱼ
Critical activities have slack = 0. Non-critical activities have positive slack — they can be delayed by that amount without delaying the project.

PERT — Probabilistic Scheduling

Three Time Estimates

PERT handles uncertainty by collecting three estimates for each activity's duration, then using a weighted average (beta distribution):

tₒ
Optimistic
Minimum reasonable time — best case scenario if everything goes perfectly
t_m
Most Likely
The most realistic duration — the mode of the distribution
t_p
Pessimistic
Maximum reasonable time — worst case if everything goes wrong
Expected (Mean) Time: tₑ = (tₒ + 4·t_m + tₚ) / 6

Standard Deviation of Activity: σ = (tₚ − tₒ) / 6

Variance of Activity: σ² = [(tₚ − tₒ) / 6]²
Total σ of Critical Path: σ_CP = √(Σ σᵢ²) [sum of CP variances]

Z-score (probability): Z = (T − T_CP) / σ_CP

Where: T = target completion date T_CP = expected critical path time

Reading the Z-table

Once you compute Z, look it up in the standard normal table to find P(complete by T):

Z0.000.250.500.751.001.161.502.00
P(Z)0.50000.59870.69150.77340.84130.87700.93320.9772

Z = 0 means T = T_CP → 50% chance. Z = 1.16 → 87.7% chance. Negative Z → less than 50% chance.

Quick Reference Summary

CPM Step-by-Step

1
Draw the project network (AON or AOA) with all activities and their durations.
2
Forward Pass: Set E₁=0, compute Eⱼ = max{Eᵢ + Dᵢⱼ} moving left→right.
3
Backward Pass: Set Lₙ=Eₙ, compute Lᵢ = min{Lⱼ − Dᵢⱼ} moving right→left.
4
Compute slack for each activity: Slack = LS − ES = LF − EF.
5
Identify the Critical Path — activities with slack = 0.

PERT Step-by-Step

1
Collect tₒ, t_m, tₚ for each activity.
2
Compute tₑ = (tₒ + 4t_m + tₚ)/6 for each activity.
3
Apply CPM using tₑ values to find the critical path.
4
Compute σ = (tₚ − tₒ)/6 and σ² for each CP activity.
5
σ_CP = √(Σ σ²_CP). Then Z = (T − T_CP)/σ_CP. Look up Z in normal table.
